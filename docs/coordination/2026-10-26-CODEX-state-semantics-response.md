## 2. READY_FOR_LOGIN 的语义

不能仅凭阶段名或 message 归类。应区分运行器是否空闲和业务任务是否就绪：

- 没有正在执行/待恢复的具体任务、会话已可用且无待办操作时，运行器应显示 IDLE，不创建需要用户响应的 Gate。
- 有具体待执行任务且前置已满足时，任务可显示 READY；运行器是否空闲是另一维度。
- 登录确实失效且阻塞某项具体工作时，建立对应待人原因；不能只因为阶段叫 READY_FOR_LOGIN 就自动产生长期 Gate。
- 有在途动作或结果不明时，先核验，不能改成 IDLE 消除异常。

修复前须核对 running/pauseRequested/任务关联及真实会话证据。WorkBuddy 记录的 11:40 假 Gate 和等待时长是当时观测，Codex 本轮未重做其根因测试，不将其当成当前全量状态。

## 3. 老数据和通知

长时间未更新不等于任务已经失效；默认标记陈旧/待核实，并与今日承诺区分，保留来源、原截止与历史。未获证据不自动删除、取消或将其完成。清退/归档需要单独规则和恢复检查。

Gate 需要能触达用户，但不得把每条旧 Gate 都无差别催办。后续在真实主动触发、准确受阻原因和通知去重基础上做时限升级；现有手动队列不等于自动唤醒。
