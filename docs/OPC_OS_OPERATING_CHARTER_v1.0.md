## 1. 北极星：净利为纲

**唯一硬标准：首店 400370 月净利 ≥ ¥12000（2026-12）**

判定规则：
- 件数（日均 ≥200）**降为过程指标**。件数不达标但净利达标 = **达标**
- 两者冲突时，**一律选净利**
- 低毛利单**可主动放弃**，不因"件数好看"而保留

**前提条款（不可省略）**：净利口径必须打通并通过复算测试。
`sales.amount.net` 不含采购/头程/包装，**当前算不准**。口径未通前，本条暂停生效——**算不准的净利不是净利，拿它当北极星等于拿假数据导航。**

**护栏（防"省出低效"）**：曝光量与转化率不得连续两周下滑。
纯净利导向会让人主动放弃冲量，排名下滑后长期净利反而更差。护栏破线即触发复核，不自动继续省。

## 2. 硬约束（四条，不可被优化掉）

| 约束 | 口径 |
|---|---|
| **时间** | **两栏，不可互相顶替**：① Lance 可用工时 ② 可购买工时（外包） |
| **现金** | 备货占用上限 + 账期倒挂窗口 |
| **账号安全** | 核心店零致命错 |
| **执行带宽** | CDP 单浏览器，并发 ≤2，生成能力排队 |

> 时间分两栏是本次裁决的直接结果：有外包，就意味着"排不下"有两种解法——少做，或者买时间。这是两个不同决策，不能混成一个。

## 3. 决策权（多角色，非单一决策者）

- **决策者**：Lance + 合伙人/助手（多人）
- **执行者**：一跨 OS（唯一经营循环执行者）

**表述修正（重要）**：
> 原设计稿「CEO Agent 是唯一权威经营大脑」→ 修正为
> **「CEO Agent 是唯一经营循环执行者，不是唯一决策权威。」**

授权来自多人，因此：
- 每条决策必须记「**谁批准的**」，不能只记"已批准"
- 多人意见冲突时，**必须显式标记待仲裁**，不许 Agent 自行合并或取平均
- Agent 不得因为"A 同意过"就推定"B 也同意"

## 4. 分店风险参数（不设全局一套）

| 店型 | 姿态 | C 档宽窄 | Kill Criteria |
|---|---|---|---|
| **核心店 400370** | 守 | **最窄** | 从严：越线即停 |
| **测试店** | 攻 | 可放宽（须有单次上限） | 从宽：给足观察窗 |

**架构要求**：风险参数必须是「店铺档案」的**字段**，不是代码里的全局常量。
同一套阈值套所有店，等于把守的店和攻的店一起拖死。

## 5. 绝对禁区（C 档白名单）

**所有店**
1. 首次真实发布上架到平台
2. 任何付款 / 采购下单 / 供应商合同
3. 删除商品 / 关闭店铺 / 动账号设置、支付、物流模板、API 凭据
4. 改目标 / 改截止时间 / 改口径定义

**核心店另加**
5. 调价（任何幅度）
6. 下架核心 SKU

**测试店另加**
7. 超过单次预算上限的投放

> 沿用已确认规则：**店小秘仅存草稿，不自动发布。**

## 6. 优先级规则

- **同时在办 ≤3**（Priority Compression）
- 冲突排序：**账号安全 > 硬截止 > 净利影响 > 其他**
- **排不下必须显式说"排不下"** + 给出被推迟清单，不许排出不可能完成的计划
- 每项任务必须能追溯到 §1 北极星或 §2 某项硬约束。追溯不到的，不是经营任务，不进 Taskboard

## 7. 验收门（顺序不可跳）

**第一门：复算测试**
随机挑 10 个展示的数字，从原始数据独立复算，必须全部一致。

**未过第一门，不得开始任何 CEO 判断逻辑的开发。**

理由：§1 选净利为纲、§7 第一门选复算——**这两条是你今天做出的最自洽的一对决定**。净利为纲要求净利算得准，而复算测试正是"算得准"的唯一证明方式。顺序反了，就是在假数据上盖判断层。

**第二门**：待定（取决于建设周期尺度，尚未裁决）
