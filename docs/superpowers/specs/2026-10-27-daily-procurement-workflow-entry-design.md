# 每日采购 workflow 入口最小接入设计

日期：2026-10-27。状态：范围已由用户明确；本设计待评审，尚未实施。

## 用户明确的目标与边界

在一跨系统的业务场景中增设每日采购启动入口和执行状态。沿用之前的 workflow：由 WorkBuddy 定时抓取数据，发送至对应 ChatGPT 对话，在对话中调用采购技能完成采购任务。用户本轮更正的是定时执行方为 WorkBuddy，接入范围不变。

一跨只负责触发和展示状态。WorkBuddy 沿用原 workflow 负责定时采集与发送；采购技能在对应 ChatGPT 对话中执行并产出结果。

## 接入方式与取舍

- 采用：薄入口接入原 workflow，展示可核验的执行状态。符合用户本轮明确边界，复用已有执行链。
- 不采用：在一跨实现采购计算、明细复核、采购单导出或独立采购执行服务。此前方案已由本轮边界替代。
- 不新建平行定时任务；WorkBuddy 原定时调度继续负责每日自动启动。

## 页面

业务场景侧栏增加“每日采购”；首页业务场景区增加同名入口，进入同一状态页面。

页面只显示：

1. “立即启动”按钮：通过已核验的触发方式启动 WorkBuddy 原 workflow 一次；已有运行在执行时禁止重复启动。
2. 当前执行状态。
3. 最近运行的实际开始时间、最后更新时间与结束时间（有证据时）。
4. 最近一次异常摘要与需要处理的事项。
5. “打开采购对话”：读取原流程当前目标地址，兼容原流程自动轮换对话。
6. 刷新状态操作。

不展示采购数量、SKU 明细、供应商、规则参数或导入表操作。

## 状态语义

| 状态 | 必须具备的依据 |
| --- | --- |
| 未启动 | 当前业务日尚无启动记录，且状态来源覆盖完整 |
| 启动已提交 | 原 workflow 已接受启动请求，尚无实际开工回执 |
| 运行中 | 对应运行有有效的执行进程或 workflow 运行回执 |
| 已发送，结果待确认 | 原流程有发送回执，但无 ChatGPT 任务最终结果回执 |
| 已完成 | 原 workflow 或 ChatGPT 对应本次运行的最终完成回执 |
| 受阻 | 有明确前置条件或业务门禁阻塞回执 |
| 执行异常 | 有本次运行的失败回执；仅发送校验失败时保留送达待核验说明，禁止盲目重发 |
| 待核验 | 状态来源不可用、记录陈旧、进程结束原因不明或不同证据冲突 |

脚本退出码 0、输入框清空、文件更新时间或有当日附件均不能单独证明采购任务完成。旧日志不得当作本次结果；无状态证据不得展示为成功、空闲或未启动。

## 已核对的本地依据

- `public/app.js` 包含业务场景导航和页面切换；`public/index.html` 包含首页业务场景卡片。
- `nawu-fetch/awu-send-to-chatgpt.cjs` 是现有采集、上传与发送执行脚本，结束于发送步骤，不等待采购任务结果。
- `nawu-fetch/chatgpt-config.json` 保存当前目标对话，原脚本在轮换后可回写地址；本次引用的“采购规则”对话不自动替换该地址。
- `send-purchase-to-chatgpt.bat` 与 `nawu-fetch/scripts/run-pipeline.sh` 是已有启动包装；后者包含浏览器前置处理。
- `nawu-fetch/.workbuddy/memory/automations/385935de-f065-42fa-a8a6-d8687d3c432f/memory.md` 为历史运行记录，仅作定位线索，不能作为实时状态接口。
- 2026-10-27 的记录包含发送脚本判断失败、独立核验已送达的情况，需保留“待核验”语义，不能自动重发。

## 实施前需由工程核验的连接条件

核验 WorkBuddy 原 workflow 当前支持的手动触发入口与执行状态来源，绑定同一 workflow 的定时及手动运行。现有脚本可用于识别执行链，但不能未经核验就把一跨直接运行脚本等同触发 WorkBuddy 原 workflow。

如果原 workflow 没有可读取的完成回执，首版只能准确显示至“已发送，结果待确认”，并提供目标对话链接；不能为补齐状态而将采购执行逻辑迁入一跨。

原目录存在其他开发者未提交修改，实施前保留并核对相关差异，只增加本功能所需接线，不覆盖或重写既有改动。

## 验收

1. 从业务场景侧栏和首页卡片均能打开同一采购状态页。
2. 启动操作调用已核验的原 workflow 入口，并返回可关联的请求/运行记录；不能仅模拟按钮成功。
3. 同一次运行中重复点击不会重复触发；定时运行与手动运行的状态能按运行区分。
4. 状态、时间和异常均来自对应运行证据；不可读取时明确显示待核验。
5. “已发送”与“已完成”严格区分；无最终完成回执不显示采购已完成。
6. 对话链接跟随原配置当前地址，不因本次引用对话自动改路由。
7. WorkBuddy 原定时、采集和发送流程，以及 ChatGPT 中的技能与采购规则保持原行为；已有业务场景可正常进入。

## Backlog

如原流程暂缺，后续补充最小完成回执；不扩展采购计算、订单、付款、SKU 表或新的定时调度。
