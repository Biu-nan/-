## 0. 结论先行（5 条，按重要性）

1. **数据可用，但不能混用接口拼一张表。** 同一产品 `1005013357807862`：榜单接口给 `7日销量 36,346`，详情接口给 `7日销量 0`——同一个 ID、同一天、差 3.6 万。另一个产品 `7日` 差 83%、`总销量` 差 6%。**必须锁定"一个指标只认一个接口 + 一个时间戳"**，否则后面所有测算都是沙上建塔。
2. **`7天销量` 不是"连续 7 天日销之和"。** `total_sales_trend` 是累计计数器，日内可跳 +3,266（某产品 10-29 从 1,492 → 4,758），而"7日销量"恰好等于这次跳变量。它本质是"采集时的累计增量"，**禁止做日差分成日销曲线**。
3. **计费坑已实锤**：传错榜单日期（keyword_rank 我用成产品榜的 2026-11-01，而关键词榜最新只到 2026-10-25）返回 `total: 0`、`error.code: 0`，**照样扣 30 积分**。截图上"响应失败不扣"只对真失败成立，空结果不在此列。**日期校验必须前置成代码，不能靠人记。**
4. **一级类目热销榜的指导价值≈0，会把你带到错误赛道。** 箱包 Top20 热销里 **68% 单品 ≤ $3**、价格中位数 **$1.83**；而你自家商品价格带在 **$19 量级**。拿这个榜选品，结论会变成"去做 $1 的行李箱轮套"，那不是你的生意。**必须下沉到二级/三级叶子类目才算数。**
5. **真正有价值的信号出现在叶子层**：`整理包（25900）` 只有 313 个商品 / 108 家店，月销 6,714 件、**供需比 2.30（全箱包唯一 >2 的非童包类目）**、Top100 均价 $5.63。这是内胆（便携式折叠包 25906）所在赛道，**供给明显不足**。

## 2. 数据质量实测（这是本次最大产出）

### 2.1 同一产品，两个接口不一致

| 产品 | 字段 | `product_rank` | `product_detail` | 偏差 |
|---|---|---|---|---|
| 1005013357807862（行李箱轮套） | 总销量 | 50,891 | 50,891 | 0 ✅ |
| 同上 | **7日销量** | **36,346** | **0** | **∞** ❌ |
| 1005012278367425（束口洗漱包） | 总销量 | 9,725 | 10,322 | +6.1% ❌ |
| 同上 | 7日销量 | 451 | 826 | +83% ❌ |

**判断**：`total_sales` 是"近一年"累计口径，两接口取数时点不同；`sales_count_7d` 在榜单侧可能是"该榜周期的增量"，在详情侧是"真实滚动 7 天"。**两者语义不同却同名，是这套 API 最危险的地方。**

**硬性设计约束（已写入建议）**：
- 销量类指标一律**只取 `product_rank`**（有 `rank_date` 可追溯），详情接口只用于取静态属性（品牌/重量/尺寸/`ships_from`/视频/`updated_time`）。
- 每条 market fact 的 `caliber` 必须含接口名，如 `market.rank.7d@product_rank`，禁止裸 `market.7d`。

### 2.2 空结果照样计费

- 传 `rank_date=2026-11-01` 给关键词榜 → 返回 `list: []`、`total: 0`、`credits: -30`。
- 说明"失败不扣"只覆盖 `error.code != 0`，**参数合法但无数据 = 成功 = 扣费**。

### 2.3 三套榜单日期各走各的

| 榜种 | day | week | month |
|---|---|---|---|
| 产品/店铺榜（normal_rank） | 最新 **2026-11-04**，但**缺 10-23~10-29** | 最新 11-01 | 最新 10-31 |
| 关键词榜（keyword_rank） | **无 day 粒度** | 最新 **2026-10-25**（比产品榜晚一周） | 最新 09-30 |

- 日榜有 7 天空洞 → 抓取器必须"按返回列表取最近可用"，不能 `yesterday()`。
- 关键词榜比产品榜**整整滞后一周** → 做"关键词 × 产品"关联分析时，两边时间窗天然错位，必须在报告里显式声明。

### 2.4 两套类目 ID 并存，别用错

榜单行同时返回：
- `category_path: [152409]` ← **AE 前台类目**（不属 IXSPY 树）
- `category_id_path: [12426, 15008]` ← **IXSPY 树**（与 13,566 节点的全量树同体系）

→ 一切类目映射只认 `category_id_path`；`category_path` 丢弃。

### 2.5 字段陷阱清单

| 字段 | 陷阱 |
|---|---|
| `store_logo` | **所有店铺都是同一张默认图**，不可用于店铺识别/去重 |
| `discovered_time = 0` | 表示"未知"，不是"1970 年"，别当新品算 |
| `sales_review_ratio` | 单条 10.2 / 19.0，含义未文档化（推断为"每评论对应销量"，即 1 评论≈10 件），**UNKNOWN，勿直接引用** |
| `ships_from: []` | 详情接口对上述 2 个产品返回**空数组**，发货地信息实际拿不到 |
| `rating = "0"` | 存在评分为 0 却有 1,037 销量的产品（新品无评价），不能当"差评品"筛掉 |
| `choice_type` | 0/1/2 = POP/半托管/全托管，与自家 Choice 半托管口径可直接对齐 ✅ |

## 5. 对原设计的三处修正

| 原设计（评估报告 §5） | 实测后修正 |
|---|---|
| facts 键 `caliber=market.*` | **必须带接口名**：`market.rank.7d@product_rank`。同名指标跨接口不可加、不可比对 |
| "先 `rank_date_list` 兜底" | 升级为**硬门禁**：`rank_date` 不在返回列表内直接拒跑（省 30 积分/次）；且 normal_rank 与 keyword_rank 各自维护 |
| 用一级类目做 P0 | **下沉到二级/三级叶子**。一级榜被 $1 配件垄断，结论会误导选品 |
