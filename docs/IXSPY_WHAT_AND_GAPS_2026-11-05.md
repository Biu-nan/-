## 一、IXSPY 是什么：一台"市场雷达"，不是第二个 ERP

### 1.1 它回答的四个问题

| 问题 | 对应接口 | 一跨现在能不能自己回答 |
|---|---|---|
| **别人在卖什么？**（某类目下哪些商品在起量） | 产品榜单（热销/增长/新品/总榜/节日榜）、产品搜索 | ❌ 不能 |
| **卖多少钱？**（价格带、Top100 均价、单品价） | 品类调研、市场洞察、产品榜单 | ❌ 不能（只有自己的供货价） |
| **什么词在涨？**（搜索量、转化率、竞争指数） | 关键词热搜榜 / 飙升榜 | ❌ 不能（现在靠模型猜） |
| **谁在抢？**（对手店铺、品类结构、上新节奏） | 店铺榜单、店铺详情、店铺品类分布 | ❌ 不能 |

### 1.2 它明确**不是**什么（这条比上面更重要）

| 不是 | 为什么 |
|---|---|
| 不是 ERP / 刊登工具 | 无写能力，不能改价、改库存、发布商品 |
| 不是自家 BI | 没有你家店的销量、结算、库存、货通拆分 |
| 不是财务系统 | 无成本、无佣金、无净利 |
| 不是实时监控 | 日榜最新 T-1，且**日期列表有空洞**（实测缺 10-23~10-29）；关键词榜比产品榜**晚一周** |

> 一句话：**IXSPY 管"要不要做、做什么、卖多少钱"，不管"我今天做了什么、赚了多少"。**

### 1.3 数据成色（实测，不是官网宣传）

| 项 | 实测值 |
|---|---|
| 分类树 | 12 MB / 13,566 节点 / 33 个一级 / 最深 4 级 / 8 个 ID 多父重复 |
| 榜单粒度 | 产品榜 1000 条（50 页）、关键词榜 5,568 条（279 页） |
| 计费 | 榜单按**请求次数**（size≤50）：1000 条完整榜 = **400 积分** |
| 数据一致性 | 同一产品在两接口的 7 日销量可差到 36,346 vs 0 |
| 空结果 | **照扣积分**（实测 3 次，共 90 积分学费） |

## 二、一跨系统的缺失清单（逐条判定）

### A. 数据缺失（系统里根本没有这类数据）

| # | 缺失 | 现状证据 | IXSPY 能补吗 | 接口 | 成本 |
|---|---|---|---|---|---|
| A1 | **选品无量化数据源** | `selection-candidates.json` 仅 **1 条**记录，字段全是 LLM 散文，带 `sourceChatUrl`——本质是"问了 ChatGPT 然后手抄" | ✅ 能 | 产品榜单 + 品类调研 + 市场洞察 | 20/页 + 30/类目 |
| A2 | **关键词无真实数据** | `mainKeyword` 是**一个 LLM 猜出来的字符串**（`config.js:235` prompt 里写"用如 Bag Charm 的英文核心搜索词"），唯一用途是填"型号/类型"两个属性（`dianxiaomi-adapter.js:3313`）。`listing-engine.js` 里**零关键词逻辑** | ✅ 能 | 关键词热搜/飙升榜 | 30/页 |
| A3 | **竞品/竞店数据为零** | `docs/CAPABILITY_REGISTRY_DRAFT.md` 20 条能力中无任何竞店条目 | ✅ 能 | 店铺榜单/详情/品类分布 | 20/页 + 2/店 |
| A4 | **价格带基准为零** | `price.adjust` 至今是 `planned`（占位不可调用）；`product-facts.json` 无市场价字段 | ✅ 能（做基准，不做决策） | 品类调研 Top100 均价 + 榜单价 | 30 + 20/页 |
| A5 | **类目 ID 映射为零** | 只有店小秘的 `categoryNameZh`（中文名），**没有 `category_id`** | ✅ 能 | 分类树资源（12 MB，**0 积分**）+ 类目搜索 | 0 |
| A6 | **区域只有自家一侧** | 内部有 400370 的 US/BR/JP/UK 分布，无市场侧对照 | ✅ 能 | 产品/店铺地区销售统计 | 3-5 |
| A7 | **SKU/变体无外部参照** | 变体主题映射只能靠猜（已知痛点） | ✅ 能 | 产品 SKU 销售分布（近180天） | 3 |
| A8 | **履约时效无对标** | 无 | ✅ 能 | 产品发货物流统计 | 3 |
| A9 | **节令/上新时机无数据** | 无 | ✅ 能 | 节日榜 + 新品增长榜 | 20/页 |

### B. 决策缺失（有数据也没有判断标准）

| # | 缺失 | 现状证据 | IXSPY 能补吗 | 说明 |
|---|---|---|---|---|
| B1 | **"这个类目值不值得做"没有量化口径** | 分层（S/A/B/M/N/C1/C2）只看**自家历史销量**，不看市场容量 | ✅ 部分 | 供需比 / 集中度 / 机会指数可做前置筛；但**公式官方未公开**，只能相对排序 |
| B2 | **"这个词该不该用"没有依据** | SEO 步骤（Listing 859 行前）全靠 prompt | ✅ 能 | 竞争指数 + 转化率可直接排出"高转化低竞争"词 |
| B3 | **"定价定多少"没有参照** | 只有供货价，无市场价带 | ✅ 部分 | 能给出价带，但**不含成本/佣金**，仍需财务侧 |
| B4 | **"对手为什么起量"无法归因** | 无 | ⚠️ 部分 | 有 SKU 分布/地区/物流/评论数，但无流量入口与广告数据 |

### C. 验证缺失（做完无法证明对错）

| # | 缺失 | 现状证据 | IXSPY 能补吗 |
|---|---|---|---|
| C1 | 上品后"选品判断是否正确"无法回溯 | 无上市基准数据快照 | ✅ 能（榜单可回溯历史日期） |
| C2 | Listing 关键词效果无法归因 | 无关键词数据 | ⚠️ 只能看市场侧搜索趋势，看不到自己排名 |

## 三、IXSPY **补不了**的三件事（别指望，也别混用）

| 缺什么 | 为什么补不了 | 仍然只能靠 |
|---|---|---|
| 自家店销量 / 支付件数 / 支付转化率 | 它是市场快照库，不含你家后台 | 销售管理 mtop（L4 已通，`sales.qty.total` 含货通 2,302 vs 不含货通 64） |
| 结算金额 / 净收入 / 佣金 | 无财务数据 | 财务管理 mtop（`sales.amount.net`） |
| 实仓 / 占用 / 在途库存 | 无库存数据 | 销售管理页字段（`inventory.audit` 能力仍未建） |

> **混用的后果**：你已经有 `sales.qty.total`（含货通）与 `sales.qty.direct`（不含）双口径，差 36 倍。再混一个市场侧"7 日销量"，会让任何利润表彻底失真。所以口径隔离写进了代码：`source=ixspy` / `storeId=market:aliexpress` / `caliber=market.*@接口名`。

## 六、一句话总结

**IXSPY 补的是一条腿：一跨现在只有"自家经营"这条腿（22 条 facts，全部来自后台），没有"市场环境"这条腿。** 缺了它，选品靠对话、关键词靠猜、定价靠感觉——三个都发生在**花钱之前**，错了要等上品跑完才知道。接上它，至少让这三个判断有了可比对的数。

但它**不能**告诉你今天赚了多少，也不会替你上架。它是望远镜，不是仪表盘。
