# IXSPY MCP 接入评估 · 一跨OS 升级需要什么

- 日期：2026-11-05
- 状态：**评估完成，未改任何代码**（仅只读实测 3 次调用，其中 2 次 0 积分）
- 输入：Lance 提供的《速卖通数据 API 计费规则 v1》截图 + 已接入的 `ixspy-data-mcp`
- 关联：`docs/L4_DATA_ARTERY_SURVEY_2026-10-25.md`（内部数据动脉）、`docs/CAPABILITY_REGISTRY_DRAFT.md`（能力清单）

## 0. 结论先行

1. **IXSPY 补的不是"另一个数据源"，而是系统当前唯一真空的那一侧：外部市场数据。** 现有 L4 数据动脉 100% 是"自家店铺经营事实"（销售管理 / 商品分析 / 财务 / 店小秘），**零条外部市场数据**。选品至今靠 ChatGPT 对话人工产出（`selection-candidates.json` 只有 1 条记录、字段全是 LLM 散文、带 `sourceChatUrl`），这是全系统最薄的一环，正好由 IXSPY 补齐。
2. **它不能替代内部数据，一点也不能。** IXSPY 没有你家店的销量、结算金额、库存、货通口径。混用会让已经踩过的"口径陷阱"再犯一次——所以接入的第一条铁律是：**`source=ixspy` 独立落 facts，`caliber` 前缀 `market.*`，永不覆盖 `sales.*` / `finance.*`**。
3. **计费有一个必须先知道的坑**：榜单类接口按**请求次数**计费，`size` 上限 50，拉完整 1000 条榜 = 翻 20 页 = **400 积分**（不是 20）。任何"先全量拉下来再说"的设计都会瞬间烧光积分。设计原则：**只拉 Top-N，按需下钻**。
4. **数据新鲜度实测**：`rank_date_list` 返回的日榜最新是 **2026-11-04**（T-1），但日期列表**不连续**（10-22 之后直接跳到 10-30，缺 10-23~10-29）。所以抓取器**不能假设"昨天一定有数据"**，必须按返回列表取。
5. **升级不需要动 L1 事实层契约，也不需要新状态机。** 新增的是 4 个 P0 只读能力（`market.*`），落点全在 F2 Capability Registry 的空白槽位里，与现有 20 条能力零冲突。

## 1. IXSPY 是什么（FACT，已核源）

| 维度 | 事实 |
|---|---|
| 定位 | 跨境电商**选品与市场数据分析平台**（不是 ERP、不是刊登工具） |
| 覆盖平台 | 速卖通 / Shopify / Etsy / Ozon / 亚马逊 / Facebook 广告（**MCP 目前只暴露 速卖通 + Etsy**） |
| 数据体量 | 官方口径：亿级商品、20 万店铺、60 万+ 供应商；6000+ 分类、4 级子分类、100+ 指标 |
| 更新频率 | 官方口径"每日全量更新"；实测榜单最新到 T-1 |
| 核心能力 | ①产品搜索（数十种过滤）②多维榜单（热销/增长/新品/总榜/节日榜）③店铺搜索与榜单 ④品类调研（月度市场体检）⑤关键词热搜/飙升榜 ⑥市场洞察 ⑦AI 分析报告（25/50 积分，**MCP 未暴露**） |
| 计费模式 | 积分制，按成功调用扣除（`error.code != 0` 不扣） |
| 与我们的关系 | 提供**市场侧参照系**：别人卖什么、卖多少、卖多少钱、哪些词在涨 |

> 关键判断：IXSPY 是"望远镜"，不是"仪表盘"。仪表盘（自家经营）已经在 L4 建完了。

## 4. 能力映射（IXSPY 接口 → 系统缺口 → 落点 → 成本）

### 4.1 可以填的（按 ROI 排序）

| 系统缺口 | IXSPY 接口 | 落点（新能力 id） | 单次成本 | 你现在的痛 |
|---|---|---|---|---|
| **选品无数据支撑** | `product_rank`（热销/增长/新品）+ `category_research` + `market_insights` | `market.selection.scan` (P0) | 20/页 + 30/类目 | 候选来自对话，无法排序、无法复现、无法 A/B |
| **关键词/SEO 靠常识** | `keyword_rank`（热搜 + 飙升，ALL/US/RU） | `market.keyword.scan` (P0) | 30/页 | SEO 步骤在 819 行跑，但没有真实搜索词依据 |
| **竞店盲区** | `store_rank` + `store_detail` + `store_category_stat` + `store_trend_data` | `market.competitor.scan` (P0) | 20/页 + 2/店 + 5 | 不知道同赛道头部在上什么、什么节奏 |
| **变体/主题映射无外部参照** | `product_orders_sku_stat` | `market.product.sku` (P0) | 3/产品 | 变体主题映射只能靠猜 |
| **定价无基准（P4 前置）** | `market_insights`（商品均价/价格带）+ `product_search(price_min/max)` | `market.price.band` (P0) | 30 + 20/页 | `price.adjust` 至今是 `planned`，因为没基准 |
| **国家分布只有自家** | `product_orders_region_stat` / `store_orders_region_stat` | `market.geo.compare` (P1) | 3 / 5 | 自家 US/BR/JP/UK 分布，无法判断"该不该进这个国家" |
| **履约时效无对标** | `product_orders_shipping_stat` | `market.logistics.bench` (P2) | 3 | Choice 半托管时效是否达标，没有参照 |

### 4.2 明确不能填的（别指望）

| 缺什么 | 为什么 IXSPY 不行 | 仍然只能靠 |
|---|---|---|
| 自家店销量/支付件数 | 它是市场快照库，不含你家后台 | 销售管理 mtop（L4 已通） |
| 结算金额 / 净收入 | 同上 | 财务管理 mtop（L4 已通） |
| 实仓/占用/在途库存 | 同上 | 销售管理页字段（L4 已通，缺聚合函数） |
| 货通口径拆分 | 平台内部规则，第三方拿不到 | 平台页面自述 + 双口径定义 |
| 刊登执行 / 草稿 / 发布 | IXSPY 无写能力 | 店小秘 |

> 一句话：**IXSPY 只解"要不要做、做什么、卖多少钱"，不解"我今天做了什么、赚了多少"。**

## 5. 接入设计（不改 L1 契约）

### 5.1 数据落点
沿用现有 facts 键，不新建表、不加状态机：

```
source   = "ixspy"                      // 与 dianxiaomi / aliexpress 并列
storeId  = "market:aliexpress"          // 三处 storeId 语义：shop: / env: / market:
caliber  = "market.rank.hot" | "market.keyword.rise" | "market.category.gmv" | ...
subject  = "<productId | storeMerchantId | categoryId>"
window   = "day:2026-11-04" / "week:2026-11-01" / "month:2026-10"
```

落盘路径沿用：`data/metrics/items/YYYY-MM-DD.jsonl`（`source=ixspy` 的行混在同一天文件里，靠 key 区分）。

### 5.2 三条硬约束（建议写进代码，不靠自觉）
1. **O 积分隔离**：抓取入口强制 `maxPages`（默认 1）+ 单次任务积分上限（默认 200），超限直接拒跑，不静默翻页。
2. **口径不可混**：`market.*` 与 `sales.*` 只允许在**诊断层**并列展示，禁止相加/相除得新指标。销评比、转化率这类跨源比值必须显式命名 `derived.*` 并标注分子分母来源。
3. **不假设日期连续**：每次抓取先 `rank_date_list`，按返回列表取，缺则写 `null + reason=DATE_NOT_AVAILABLE`（沿用 L4 的"绝不沿用昨日值"）。

### 5.3 建议节奏
| 阶段 | 内容 | 积分/月（估算） |
|---|---|---|
| **P0（本周可做）** | 1 个类目（箱包 12426）跑通全链路：品类调研 → 产品榜单 Top50 → Top10 详情 → 关键词榜；产出 1 份"市场 vs 自家"对照报告，人工核验准确率 | ~350（一次性 + 首月） |
| **P1** | 固化为周任务：3 类目 × 榜单 1 页 + 关键词 1 页 + 竞店 Top10 趋势 | ~700–900 |
| **P2** | 接入 L3 诊断环：market facts 作为 `selection` 层输入，进 `stratify` 的上游 | ~1,200–1,500 |

> 以上为 **INFERENCE**（按 §2 价目表 × 调用次数推算），未含 AI 分析（25/50 积分/次，MCP 未暴露）。真实预算必须等你给我积分余额后才能定。

## 7. 一个容易被忽略的风险：别让"数据丰富"变成"决策噪音"

现有系统的强项是**口径干净**——22 条 facts，每条都有 `caliber` 和 `status`，缺了就写 `null`。IXSPY 一接进来，指标数量会从 22 条跳到几百条，且**大部分是别人家的数**。

三条建议：
1. **先进诊断、后进决策**：P0 阶段 market facts 只用于"生成候选 + 人工复核"，**不允许直接触发上品**。上品链路的入口仍然只有一个（现有 `product.onboard`）。
2. **每个 market 指标必须能回答"所以我该做什么"**，答不上来的指标不接。比如"某类目总销量"单独存在无意义，必须配"该类目 TOP50 的价格中位数 vs 我的供货价"才可用。
3. **保留反证**：P0 报告必须包含"IXSPY 说有机会，但自家数据不支持"的条目。只报喜的报告等于没做。

## 7.5 抽样验证已执行（2026-11-05）

P0 抽样已跑完（箱包 12426 端到端，实扣 114 积分），结果见 `docs/IXSPY_P0_VALIDATION_2026-11-05.md`，原始证据 `data/market/ixspy/2026-11-05/evidence-12426.json`。

三条实测事实**推翻了本文档 §5 的部分假设**：

1. 同一产品在 `product_rank` 与 `product_detail` 返回的 `sales_count_7d` 不一致（36,346 vs 0），`caliber` 必须带接口名，禁止跨接口混算；
2. 传错 `rank_date` 返回空结果**仍扣 30 积分**，日期校验必须是硬门禁而非兜底；
3. 一级类目热销榜被 $1~$3 配件垄断（68% 单品 ≤$3，一家店占 82%），**P0 范围应下沉到叶子类目**。

- **未改任何代码、未新增文件（除本文档）、未调用任何收费接口**（实测 3 次：`category_resource` 0 积分、`rank_date_list` 0 积分）。
- 所有"应该怎么做"的部分均为建议，等你 A1–A4 拍板后才进入实施。
- 数据事实（分类树 13,566 节点、33 一级、最深 4 级、日榜最新 11-04、日期不连续）为**实测**；成本估算为**推算**；销量口径为 **UNKNOWN**（列在 B1）。
