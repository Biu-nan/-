## 1. 目标与底层原则（图的底线，不得违背）

- **生命周期先判断**，经营诊断只**解释原因**，库存策略**再**生成采购。
- **影子计算与正式生效分离**：新规则先影子跑对照，人批后才正式生效。
- **UNKNOWN / 冲突时不得强行出正式结论**（数据不足/矛盾 → `UNRESOLVED`，不覆盖系统事实）。

---

## 2. 五大独立管理维度（禁止混用）

1. **产品开发阶段**：录入素材 → Listing 制作 → QC
2. **平台刊登状态**：未开始 / 发布中 / 已发布 / 暂停 / 下架
3. **商品生命周期**：E 新品观察 / G 成长 / C 长尾 / D 沉睡（+ UNRESOLVED）
4. **经营诊断**：表现等级 S/A/B（A/B/C/D/E 资金层级另属资金，不在本层）
5. **库存执行策略**：STOCK / LIGHT_STOCK / ORDER / ORDER_观察

> 硬规则：**生命周期 ≠ 销量等级 ≠ 资金层级 ≠ 刊登状态**。实现上必须分表/分字段存，禁止用「销量」直接当「生命周期」。

## 3. 商品生命周期状态机（核心整改）

### 3.1 状态与默认窗口
| 状态 | 含义 | 进入/退出要点 |
|---|---|---|
| **E 新品观察** | 已上架且可售 | 默认 **21 个有效可售日**；主推期按销售额；累计销量；**不能用 ERP 最后记录替代** |
| **G 成长** | 满足毕业条件 | 趋势驱动补货 / 危货处理 / 供货稳定性 / 新旧品重算出口日期 / 趋势保障判定 |
| **C 长尾** | 达长尾条件 | 尾量补货 / 增长观察 / 增长诊断 / 增长恢复 |
| **D 沉睡** | 达沉降条件 | 主动备货=0 / 最低库存维持 / 不填默认周期补货 / 不主动清货 |
| **UNRESOLVED** | 冲突多 / 数据不足 | **暂不更新正式生命周期**，转「恢复增长观察」 |

### 3.2 转移判定（按图顺序）
1. E 期内：**是否满足毕业条件？** 是 → **G**；否 → 继续。
2. 21 个有效可售日已够？否 → 继续 E；是 → **13/14 日销量分辨**：
   - 达「沉降条件」→ **D**；
   - 达「长尾条件」→ **C**；
   - 否则保持观察（下拉观察期）。
3. G 期出现下降 → 下降观察第 1/2/3 个 14 日窗口 → 第 2 个窗口仍未恢复 → **降级评估**。
4. C/D 出现「恢复增长」信号 → 恢复增长观察 → 通过则回升。

**毕业条件（E→G）**：累计销量 ≥10；近 7 日销量趋势达标；矛盾取证（D≥2）；证据完整。

### 3.3 ⚠️ 待最终确认的冲突阈值（**不要猜，等 Lance 定**）
- **E→G 近 7 日阈值：7 还是 8？**
- **C/D 边界：5 还是 6？**

## 4. 经营诊断层（解释原因，不替代生命周期）

| 码 | 名称 | 触发 | 动作 | 现有数据可得性 |
|---|---|---|---|---|
| A | TRAFFIC_WEAK | 曝光/访客下滑 | 查流量入口/广告/排名 | ✅ 有 exposure/visitor |
| B | CTR_WEAK | 点击率下滑 | 查主图/价格/标题 | ❌ 缺 clicks/impressions（无法算 CTR） |
| C | CVR_WEAK | 转化下滑 | 查详情/评价/竞争力 | ✅ 有 pay_buyer/visitor 可算 |
| D | SUPPLY_BLOCKED | 缺货/断货/断供 | 先恢复供货 | ✅ 有 real/locked/inroad |
| E | DEMAND_WEAK | 销量正常但库存异常 | 评估真实需求 | ✅ 有销量+库存 |
| F | DATA_UNRELIABLE | 采集失败/字段矛盾 | 暂停自动判断，人工核验 | ⚠️ 需自建校验 |

> 铁律：**销售下降 ≠ 一定进沉睡**；先判断是流量、转化、供给，还是需求真实下降。

## 5. 生命周期 → 采购

### 5.1 库存策略引擎（按生命周期）
| 生命周期 | 主动备货 | 策略 |
|---|---|---|
| E 新品观察 | 低补货 | **优先根据真实需求**（≤10 起量） |
| G 成长 | 拉满销量阈值 | 趋势驱动 |
| C 长尾 | 按销量+利润加权 | 尾量补货 |
| D 沉睡 | 不主动补货 | 维持最低 |

### 5.2 统一净需求计算（图内要点）
- 实仓**分渠道**库存（自营 / 官方 / JIT 分别决策）
- **有效在途不可超发**
- 历史采购回撤合规
- 官方仓 vs JIT 分别算

### 5.3 官方仓 25 天公式（**图内原文，需确认**）
```
ADS = (历史销量7天×7 + 30天销量) / 7     ← 写法存疑，见 §10-Q3
目标 = 上调 ADS × 25
```
> 现有 Agent 用的是 `覆盖天数 = 物理可用 / (30d销量/窗口)`，与本式**不同**，需明确采用哪个/如何合并。

## 6. 三层产物 + PDCA + 影子/正式分离

- **L1 全量评审表**：含旧值 / 新值 / 证据 / 计算过程（可全量复核）
- **L2 采购决策表**：按 14 天导入、字段可信度、采购量、审核价
- **L3 人工验证清单**：供应商 / 价格 / ETA / 入仓
- **PDCA**：P 发现问题（数据异常/人工纠偏）→ A 固化版本（版本名/计算/变更指令）→ C 验证效果（留存测试/影子计算/对照）→ D 执行整改（规则/版本/流程修订）
- **影子 vs 正式**：新规则先写「影子表」跑对照，**人批后**才写「正式表」；两表分离，不互相覆盖。

## 7. 现有 Agent 与本图的映射

| 本图概念 | 现有实现 | 复用/改造 |
|---|---|---|
| 物理可用 | `actual − occupied + transit` | ✅ 可复用为「单渠道基线」 |
| 覆盖天数 | `物理可用 / 日均` | ✅ 可复用，但需接生命周期权重 |
| DEAD_STOCK | 近30天零销且累计≥50 | ⚠️ 近似 D 沉睡，但**无 21/14 日窗口、无转移** |
| 五结论 | RESTOCK/WATCH/OVERSTOCK/DEAD_STOCK/NO_HISTORY | ⚠️ 是「库存策略」层，缺上游生命周期门 |
| 红线/失败码 | sellsale禁/金额0/拆单/日切拒 | ✅ 全部保留，扩到新层 |
| Workflow/Gate/回读 | 已实现 | ✅ 直接复用为「正式生效」通道 |

## 9. 分阶段落地计划（每阶段独立验收，影子先行）

- **Phase 0（本轮）**：本对齐稿 + 冲突决策清单 + 数据缺口清单。✅ 现在交付。
- **Phase 1 五维数据模型**：生命周期/刊登/诊断/资金层级分表存，禁止混用；补「上架日期、有效可售日」采集。
- **Phase 2 生命周期状态机**：E/G/C/D/UNRESOLVED，21/14 日窗口，冲突归 UNRESOLVED；**先影子只出对照表，不生效**。
- **Phase 3 诊断层**：先上 A/C/D/F（数据够），B 待 clicks。
- **Phase 4 净需求+渠道**：统一净需求、有效在途不可超发、回撤、渠道拆分；产出 L1/L2/L3。
- **影子→正式**：影子跑 ≥N 天与人对照，人批后才切正式。
