02
容量门
Capacity Gate

所有排程必须先过的唯一闸门新增 · P0

工时预算
本周可用小时（扣除不可用时段），按高/中/低精力档分段
现金额度
备货资金上限、账期倒挂窗口、铺货占用
执行带宽
浏览器会话、并发 ≤2、生成能力排队
门禁逻辑
先扣容量再排任务；不足时必须显式输出「排不下」+ 被推迟清单
为什么必须有：一人公司唯一的硬约束是可用工时与现金，不是数据量或 Agent 数量。V0.2 把「资源与预算」压在最顶层一个人形里，等于没有约束。闭环稿 §5 C1「只有四小时先补货还是改标题」已经把时间容量当一等约束——本层就是把那条逻辑提成架构承重墙。

运行保障
Operations

节奏 · 例外 · 降级新增

节奏引擎
日：店铺监控/订单库存/异常
周：WBR 复盘（固定议程 + 记分板）
月：利润结构 / 库存结构 / 放弃评审
季：品类布局 / 供应链 / 目标重定
例外管理
Agent 全量汇报 = 噪声。只让三类事升级到人：越过警戒线、临近硬截止、需裁决。无变化不刷屏。
降级模式
人不可用 / 断网 / 浏览器挂 / 模型不可用 → 系统只读运行 + 保留任务现场 + 恢复先回读，不重跑有副作用流程。

不可越过的红线（继承自定位稿与项目记忆）

  • CEO Agent 是唯一经营大脑，不允许其他模型在 OS 内替代其决策
  • 不先引入 Temporal / LangGraph；演进按 F1 → F5 顺序
  • 未审定设计不得据旧任务开工；planned / unverified 不自动执行
  • capacity 不足时必须显式说排不下，不许排出不可能完成的清单
  • Agent 不得直读原始表，必须经语义层（防漂亮但错误的结论）
  • 写操作唯一入口；同机单写执行 + 上下文版本检查
  • 「接受主动经营」≠ 对发布/采购/改价/删除的无限授权
  • 任务完成率与经营效果分开衡量，不能承诺完成任务即达成销售
