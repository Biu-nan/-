06跑不动了怎么办：异常与降级

数据过期 / 口径冲突
停止使用该数字做判断，界面标灰。建立补证任务，其他任务继续
平台规则突变
停止受影响且未提交的动作 → 重评 → 保留旧审批处置。不许按旧规则硬跑
人不可用 / 断网 / 浏览器挂
系统只读运行，保留任务现场。恢复后先回读，不重跑有副作用流程
提交超时 / 结果未知
先回读核实对象与状态。没有确认前不许重建、不许重试
容量不足
显式输出"排不下" + 被推迟清单。禁止排出看起来能完成的假计划
多人意见冲突
标记「待仲裁」，挂起不执行。Agent 不得自行合并、取平均或替任何一方推定

07启动顺序：第一周真正要跑起来什么

不是七步全建，是先让回路有一个能跑通的窄环。
Day 1–3
打通净利口径 + 让口径门生效
把 metrics-schema 变成运行时守门；补足采购/头程/包装成本项，做出可复算的单品净利。目标：过复算测试
Day 4
用真实数据跑一次复算测试
随机挑 10 个数字，从原始数据独立复算。全对才进下一步；有一个不对就停下来修口径
Day 5–6
建决策记录与假设记录的最小写入
只要字段能写、能按对象检索即可。先让它记得住，再让它想得对
Day 7
晨间一屏（只读版）
结论/红线/三件/待决/观察中。此时不含任何 Agent 判断，数据全部来自已过门的口径
本周不做
CEO 判断逻辑 · 容量门自动化 · 3 个 Agent · 外部信号采集
