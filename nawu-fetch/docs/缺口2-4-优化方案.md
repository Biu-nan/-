## 1. 缺口 3：仓库清单属性补齐 —— 已落地 ✅

### 1.1 实测证据（2026-10-11）

| 事实 | 证据 |
|---|---|
| 仓库清单 SKU ↔ 商品管理 SKU 完全命中 | `1888 / 1888`，仓库未匹配 **0** |
| 商品管理「状态」列已含配对状态 | `在售 「已配对」`×1267、`在售`×621 |
| 商品管理有**互斥类型页签** | `全部(1888) 单品(1739) 组合(146) 多变种(3) 加工(0) 有异常(7)` |
| 页签可点、可翻页 | 点「组合(146)」→ 渲染 100 行并声明 total=146 |
| 组合行带「组合详情」链接 | 组合行商品信息含 `组合详情`（BOM 的取数入口） |

#### 三个实测「坑」（都已在代码内规避）

1. **页签连续切换会渲染空表**：先点「组合」再点「多变种」时，页签虽激活（`activeTab=多变种(3)`）但表格 **0 行且无分页器**——店小秘前端缺陷。对策：该页签采不到行时**重新加载页面**再点（新加载即为首操作，可正常出 3 行）。
2. **多变种是树形且默认折叠**：父行（`100004`，无 SKU，`已有变种：1`）+ 子行（真实变种 SKU）。子行**延迟渲染**，需点父行「变种详情」展开才出现。
3. **子行走的是另一段 colid**：父行用 `col_6..col_15`，子行用 `col_66..col_74` / `col_38..` / `col_52..`——**根本没有 `col_9`**。故解析必须 **colid 无关**（按「含 `[编码]` 或非数字锚」定位商品信息单元格），并跳过 `is--expand-row` 父行。
   结果：多变种真实 SKU = `QTJLC049-2 / QTJLC049-4 / QTJLC049-5`（均存在于商品清单）。

#### 一致性判据（防伪造的关键）

| 判据 | 含义 |
|---|---|
| `enumerationComplete` | 每个类型页签「页面声明数 == 实得数」 |
| `singlesClosed` | 把「非组合/多变种/加工」默认成单品后，单品总数与页面声明**闭合** |
| `typeAvailable = 两者皆真` | 只有此时才允许把剩余 SKU 标为「单品」；否则记 **UNKNOWN** |

实测最终结果：`declared == collected = {组合:146, 多变种:3, 加工:0, 有异常:7}` → **闭合**；单品推定 1739 == 声明 1739。

## 2. 缺口 2：商品管理附加字段 —— 分层解决

### 2.1 决定性事实

实测「导入/导出」下拉（`ant-dropdown-trigger`）内容为：

```
导入： 导入单个SKU商品 / 导入多变种SKU商品 / 导入组合SKU商品 / 导入加工SKU商品 / 导入平台SKU / 导入供货关系 / 导入商品状态
导出： 按勾选导出 / 按页导出 / 按所有页导出
```

→ **没有「自定字段 / 导出设置」入口**。因此「导出」拿不到供应商、来源URL、BOM、组合数量。
（规格原文也预留了这条路径：*"若导出模板没有…可在只读权限下从相应商品详情补充到独立数据文件"*。）

### 2.2 三层策略

| 层 | 字段 | 取数方式 | 成本 | 状态 |
|---|---|---|---|---|
| L1 | **1688配对状态** | 商品管理「状态」文本派生（`在售 「已配对」`） | 0（已随 join 得到） | ✅ 已落地 |
| L2 | **组合BOM / 组合数量** | 组合页签行点「组合详情」 | 仅 **146** 条，一次抓完 | 路线已验证，待你确认是否每轮全量 |
| L3 | **首选供应商 / 来源URL / 商品来源平台** | 商品详情页（只读） | 全量 1888 条偏高 → **建议只对进入采购候选池的 SKU 按需取** | 待你选触发方式 |

另有一条**旁证**：商品管理下拉里存在「**导入供货关系**」，说明系统内有 SKU×供货商的映射数据；`任务07` 已抓到汇总级 `supplyRelation`（供货商名称/供货商品数），**SKU 级映射**需再从供货关系详情或商品详情取。

### 2.3 建议触发方式（二选一）

- **A｜按需（推荐）**：只对 C6R 引擎当轮**候选采购 SKU**（通常几十条）取 L3，落 `normalized/<日期>/sku-supplier-detail_*.xlsx`。成本可控、与采购决策强相关。
- **B｜全量**：每轮对 1888 条全量开详情。字段最全，但耗时显著上升，且大部分与当轮采购无关。

## 3. 缺口 4：采购主数据 —— 脚手架已交付 ✅（待你填规则）

### 3.1 为什么必须由你提供

规格 §二·任务07 明确：
> *"资金层级、生命周期参数和 C6 冻结规则**不一定存在于店小秘**。缺失时应从已经确认的本地采购主数据中获取，**不得凭历史销量自行伪造层级或交期**。"*

### 3.2 交付物

| 文件 | 作用 |
|---|---|
| `lib/master.cjs` | 主数据核心库：模板列、受控词表（A–E / STOCK·ORDER·LIGHT_STOCK）、BOM 解析、一致性校验（含 **BOM 环检测**、**别名环检测**） |
| `scripts/master-import.cjs` | 导入 CSV/XLSX → `master/sku-master.json` + **`master/versions/sku-master.<version>.json` 不可变快照**；`--init` 生成填空模板 |
| `scripts/master-validate.cjs` | 只读校验当前版本（或 `--file` 指定），输出 ERROR/WARNING 与 `VERDICT: PASS/FAIL` |
| `master/sku-master.template.{csv,xlsx}` | **填空模板**（已生成，含 1 行示例） |
| `docs/采购主数据填写说明.md` | 填写说明 |

### 3.3 使用方式

```bash
# 1) 生成/刷新填空模板
node scripts/master-import.cjs --init

# 2) 填好后导入（按版本归档，不覆盖已确认版本）
node scripts/master-import.cjs --file master/sku-master.csv --version v1 --by Lance --note "首次录入"
#    有 WARNING 时需显式 --allow-warnings 才会写入；有 ERROR 一律拒收

# 3) 随时只读校验
node scripts/master-validate.cjs
```

模板列：`原始SKU | 基础物料SKU | 规范化SKU | 旧编码 | 新编码 | 资金层级 | 生命周期分层 | 采购模式 | LT1交期天 | 深度代发 | 组合子SKU | 组合数量 | 首选供应商 | 采购参考价 | 来源平台 | 来源URL | 1688配对状态 | 特殊采购例外 | 规则版本 | 生效时间 | 变更来源`

> 组合件写法：`组合子SKU` 列用 `;` 分隔，形如 `WDZ01*2;WDZ02*1`（`*` 后为用量）。

### 3.4 门禁与纪律

- ERROR：层级不在 A–E、模式不在 STOCK/ORDER/LIGHT_STOCK、LT1 非正整数、原始SKU 重复、BOM 环 → **拒绝导入**。
- WARNING：BOM 子件未建档、规范化与内置字符规则不一致、配对状态词表外 → 需 `--allow-warnings` 才可入库。
- **推断后门 = DISABLED**：校验器不会用历史销量补齐任何层级/交期/BOM。
