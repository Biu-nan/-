# 采购主数据（sku-master）填写说明

> 这是 **C6R 采购执行侧唯一的人工权威主数据**。资金层级、生命周期、采购模式、LT1 交期、组合 BOM **只来自你确认过的规则**。
> 系统**不会**用历史销量推断这些值；缺失项请留空（会记为未知），不要"猜一个填上"。

## 1. 三步走

```bash
# ① 生成/刷新填空模板（在 nawo-fetch 目录下）
node scripts/master-import.cjs --init
#    -> 纳物采购最新数据/master/sku-master.template.csv
#    -> 纳物采购最新数据/master/sku-master.template.xlsx

# ② 复制模板，填好后另存为（例如 sku-master.csv），然后导入
node scripts/master-import.cjs --file master/sku-master.csv --version v1 --by Lance --note "首次录入"

# ③ 随时只读校验
node scripts/master-validate.cjs
```

结果：
- `master/sku-master.json` —— 当前版本（引擎读取这个）
- `master/versions/sku-master.v1.json` —— **不可变**历史快照（换版本号追加，不覆盖）

> 有 **ERROR** → 拒绝导入，什么都不写。
> 有 **WARNING** → 需加 `--allow-warnings` 才可入库（建议先看清单再决定）。

## 2. 列说明

| 列 | 必填 | 说明 |
|---|---|---|
| 原始SKU | ✅ | 店小秘里的**原始** SKU 字符串，原样保留，不要改写 |
| 基础物料SKU | | 组合/加工件背后的**真实物料** SKU；等于 原始SKU 时可不填 |
| 规范化SKU | | 仅**新建档**时按规则 `# → _`、`* → X`、`+ → /`、`空格 → -`；历史 SKU 原样保留 |
| 旧编码 / 新编码 | | 新旧编码映射关系 |
| 资金层级 | | **只能是 A / B / C / D / E** |
| 生命周期分层 | | 你的分层命名（如 主推 / 常规 / 清仓），自由文本 |
| 采购模式 | | **只能是 STOCK / ORDER / LIGHT_STOCK** |
| LT1交期天 | | **正整数**（天） |
| 深度代发 | | 是 / 否（也接受 1/0、true/false） |
| 组合子SKU | | 组合件子件，`;` 分隔：`WDZ01*2;WDZ02*1`（`*` 后为用量） |
| 组合数量 | | 单子件时可用此列给用量（多子件请用内联 `*数量`） |
| 首选供应商 | | 供应商名称 |
| 采购参考价 | | 数字（元） |
| 来源平台 / 来源URL | | 如 1688 + 商品链接 |
| 1688配对状态 | | 已配对 / 未配对 / 未知 |
| 特殊采购例外 | | 已确认的例外说明（自由文本） |
| 规则版本 / 生效时间 / 变更来源 | | 追溯用；如 v1 / 2026-10-11 / Lance |

## 3. 会被拦下的错误（ERROR）

- 资金层级 不在 A–E
- 采购模式 不在 STOCK/ORDER/LIGHT_STOCK
- LT1交期天 不是正整数
- 原始SKU **重复**（一个 SKU 只能一行；组合多子件请用「组合子SKU」列分隔）
- BOM **循环引用**（A→B→A）

## 4. 只是提醒（WARNING）

- 组合子SKU **未在本次主数据里建档**（可能在其他批次，请确认）
- 填了规范化SKU 但与内置字符规则结果不一致（历史 SKU 可保留，需你确认）
- 1688配对状态 不在词表内

## 5. 版本与追溯

- 每次导入都写一个**新版本**快照到 `master/versions/`，历史版本**永不覆盖**。
- 若版本号已存在，导入会被拒绝（除非显式 `--force`，不推荐）。
- 换规则时**请改版本号**（v1 → v2），并在 `变更来源` 写明原因。
